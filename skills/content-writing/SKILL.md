# 内容写作规范

把「值得写清楚的东西」写成读者愿意读完、且经得起事实检验的文章。技术文章靠准确与可复现建立可信，营销文案靠共鸣与可信促成行动。

## 核心原则

1. 动笔前必须能用一句话说清「读者读完能带走什么」；说不清就不写。
2. 先定读者、目的与平台，再决定语气、结构与长度；不以字数当目标。
3. 每个事实、数字、案例、命令都有来源；没有来源的内容宁删不写。
4. 先写清再写短：第一遍允许啰嗦，第二遍删到没有一句话可再删。
5. 反 AI 味：禁用套话与模板腔，用具体细节支撑，而非形容词堆砌。
6. 一个主旨、一条主线；一篇只解决一个问题或一个决策。
7. 输出语言默认中文，专业术语保留英文；用户指定其他语言时遵从其要求。

## 先定文体

动手前先二选一：

- **technical（技术文章）**：讲「怎么做 / 为什么 / 原理」。价值 = 准确 + 可复现。适用于教程、源码解读、踩坑记录、方案对比、原理剖析。
- **marketing（营销文章）**：讲「为什么选我 / 你能得到什么 / 现在行动」。价值 = 共鸣 + 可信 + CTA。适用于产品宣传、获客转化、品牌故事、落地页文案。

缺省判定：以「传授或沉淀知识」为主 → technical；以「促成点击 / 咨询 / 购买」为主 → marketing。技术软文以 marketing 目的为主线、technical 事实做支撑，不两头漂移。两条路径的骨架与红线见 `references/technical.md` 与 `references/marketing.md`。

## 写作前 7 问（任何文体都先过）

1. **读者是谁**：水平、平台、痛点。
2. **一个主旨**：一句话说清「读完带走什么」。
3. **关键词 / 选题**：读者会搜什么；标题与主旨是否命中。
4. **目的与 CTA**：technical 多为「收藏 / 关注 / 深入学习」，marketing 为「试用 / 咨询 / 购买」。
5. **语气与长度**：由平台与受众倒推，不是越长越好。
6. **事实来源**：technical 要可运行代码 / 命令 / 数据；marketing 要真实案例 / 数字 / 客户证言。
7. **发布格式**：Markdown 或平台富文本；是否需要首图、摘要、标签、封面文字。

写得出来才动笔；第 2、6 问答不上来就停下，先和用户澄清。

## 主流程

1. 定文体与 7 问，锁定单一主旨与目标读者。
2. 收集一手资料：technical 以「真实运行通过」为准，marketing 以「真实案例 / 数据」为准。
3. 搭结构骨架（technical 结构或 PAS/AIDA 见 references）。
4. 写初稿：允许啰嗦，先求完整、准确、有细节。
5. 事实核查：逐条核对数字、代码、命令、链接、版本、人名与引用；见 `references/checklist.md`。
6. 反 AI 味与校对：删套话、删冗余、统一术语与格式；见 `references/checklist.md`。
7. 按平台要求输出成品及其摘要、标签、封面文字。

## 两条路径的红线

technical：代码必须真实可跑、命令需在真实环境验证；写清适用边界与不适用场景；每个结论有来源并标注版本。

marketing：禁空话，无具体数字 / 案例 / 证言就不许写「提升」「领先」等词；一篇文章只推一个动作、一个主 CTA；痛点只针对你真实服务的群体。

## 输出要求

完成后简洁输出：① 文体与目标读者；② 一句话主旨；③ 使用的骨架（technical 结构或 PAS/AIDA）；④ 关键事实及其来源；⑤ 字数与所在平台格式；⑥ 待用户确认的可选项（标题备选、语气倾向、是否插入图片 / 代码位置）。不得虚构来源、数据或用户评价。
